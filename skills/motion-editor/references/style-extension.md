# Как добавить самостоятельный стиль

Применяй, когда владелец просит придумать/подключить новый переиспользуемый стиль. Разовая адаптация одного видео не обязывает менять весь skill; оставь её внутри выходного проекта, пока не запрошено повторное использование.

## Граница ответственности

Родитель: смысл/речь/EDL/тайминг/защищённые области/сборка/форматы/общая QA.
Стиль: типографика, палитра, material и cutout grammar, композиционные приёмы, движения, состояния предметов, переходы, подбор стилевых ассетов и собственная QA.
Shared runtime: маленькие геометрические/временные helpers и типы. Их использование необязательно, если модулю нужен собственный primitive. Не тащи в shared особый рекламный бейдж или частный фон только ради нового стиля.

## Структура

```text
styles/
  registry.json
  new-style-id/
    style.json
    SKILL.md
    Scene.tsx
    evals.json
    assets/
```

assets необязателен; создавай его лишь при реальных файлах. evals.json — несколько задач и критериев только этого языка, без личных исходников. Имена папок — kebab-case. Точка входа и код каждого стиля самостоятельны.

## Manifest

Пример формы, без команды автоматически регистрировать недоделанный модуль:

```json
{
  "schema_version": 1,
  "id": "new-style-id",
  "name": "Название нового стиля",
  "aliases": ["уникальное имя референса"],
  "keywords": ["отличительный визуальный признак"],
  "skill": "SKILL.md",
  "renderer": "Scene.tsx",
  "defaults": {
    "title": "Заголовок",
    "subtitle": "Подпись",
    "labels": ["Начало", "Действие", "Результат"],
    "accent": "#4263eb"
  },
  "capabilities": ["fullscreen", "lower-panel"],
  "version": "1.0"
}
```

Пути skill/renderer относительны папке manifest, не выходят из неё. Aliases и IDs не конфликтуют с другими модулями. Keywords — отличительные, не общие слова «монтаж», «красиво», «видео», которые захватывают все запросы.

SKILL.md: собственные name/description, вход от родителя, обещаемый выход, visual grammar, три предметных рецепта на разных темах, ограничения, style-specific проверки и точность ассетов. Не дублируй весь workflow родителя. Новый стиль не наследует автоматически остальные стили и не копирует их инструкции ради объёма.

## Renderer API

```tsx
import React from 'react';
import type {StyleSceneProps} from '../../assets/scene-kit/shared';
export const StyleScene: React.FC<StyleSceneProps> = ({c,f,span,compact}) => {
  // Return this style's actual frame-driven scene; implement before registration.
  return <div />;
};
```

Это иллюстрация сигнатуры, не готовый renderer. Пустой компонент не проходит визуальную приёмку. c — SceneConfig (style:string, размеры/FPS/duration, title/subtitle/labels/accent, layout, optional panel/backgroundVideo/images); f/span — локальный кадр/длительность; compact — нижняя панель. Дизайн-система core даёт canvas1080×1920 для fullscreen и1080×720 для compact, затем масштабирует/обрезает. Родитель ограничивает движение панелью, стиль сохраняет читаемую внутреннюю композицию.

Import paths сохрани относительно style folder; не импортируй active canonical package абсолютным путём. Для нескольких экземпляров SVG filter/path IDs должны быть уникальными. Используй только реально доступные зависимости и локальные подготовленные ассеты. Не добавляй новый платный сервис как скрытое требование стиля.

## Регистрация и проверка

1. Зафиксируй исходный референс/эстетику и критерии; отличай observed и invented. Для нового авторского языка назови допущения.
2. Создай модуль в staging либо проектной копии, не ломая существующие стили.
3. Добавь единственную строку `new-style-id/style.json` в массив styles реестра. Родительский SKILL и общий render core менять не нужно.
4. Запусти `python3 scripts/style_registry.py --validate`, затем выбор по ID/alias и неизвестному имени. Проверь отсутствие коллизий и escaping paths.
5. Создай проект через scaffold с новым ID. Он сам обнаружит module и сформирует проектный каталог renderer-компонентов. В созданном scene.json можно переключать только зарегистрированные на момент сборки стили; старые созданные проекты не обновляются сами.
6. Реально отрендери короткую сцену, посмотри движение/читаемость/новую тему и compact при заявленной capability. Сохрани source и результаты; не объявляй новый стиль рабочим по пустому div или успешному JSON-линту.
7. Проверь прежние IDs/aliases/CLI и пару старых сцен. После исправлений зарегистрируй проверенный module в каноническом пакете в уже разрешённом владельцем объёме. Новый ID не должен требовать нового if/elif в общем коде.

Если нужны assets/fonts, которых нет, укажи missing/approximation и не обещай точную копию. При отсутствии необходимых инструментов подготовь пакет и назови конкретный блокер вместо фиктивного MP4. Публикация, глобальная установка и оплачиваемые внешние действия остаются отдельным scope.
